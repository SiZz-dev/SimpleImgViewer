# UX 휴리스틱 점검 (리뉴얼 1단계)

2026-11-19, 커밋 `25e81bb` 기준 화면을 점검했습니다. 디자이너 없이 진행하는 UI/UX 리뉴얼의 첫 단계로, **무엇을 왜 바꿀지**를 정하는 근거 문서입니다. 다음 단계는 디자인 토큰 정리 → 시안 비교 → 단계적 반영 → 사용성 확인입니다(7절).

## 1. 방법

- **기준**
  - Nielsen 10 휴리스틱
  - WCAG 2.2 AA 일부: 대비 1.4.3, 키보드 2.1.1, 포커스 2.4.7, 대상 크기 2.5.8
- **심각도**(Nielsen 0~4)
  - 4: 사용을 막음
  - 3: 큰 문제, 우선 해결
  - 2: 작은 문제, 다음 순위
  - 1: 겉모양 문제
  - 0: 문제 아님
- **환경**
  - 임시 저장소의 개발 서버, 합성 표본(PNG 1200×800, 2페이지 GIF, MP4, WAV)
  - 앱 내장 브라우저로 1440×900 다크·라이트와 375×812 모바일 에뮬레이션을 확인했습니다.
- **확인한 화면 상태:** 빈 화면, 이미지(메모 1개), 스탬프 도구 오류, 동영상, 라이트 테마, 모바일(패널 열림/닫힘)
- **측정:** 스크립트로 글자 크기 분포, 대비율, 클릭 대상 크기, 도구 패널 스크롤 위치, 키보드 접근 여부를 쟀습니다. 단축키·드래그 앤 드롭·터치 제스처가 있는지는 코드로 확인했습니다.
- **한계**
  - 점검자는 1명(AI)이고, 실제 사용자 테스트는 하지 않았습니다(7절 5단계에서 보완).
  - 표본이 단순해서 고해상도·세로형 이미지와 긴 파일명은 따로 확인해야 합니다.

## 4. 잘 된 점 — 리뉴얼에서도 유지

- 다크·라이트 테마, 한 줄 헤더, 양쪽 접이식 패널이라는 기본 배치가 도구형 뷰어에 맞습니다.
- 아이콘 버튼마다 `aria-label`과 `title`이 있고, `:focus-visible` 포커스 표시가 있습니다.
- 대부분의 텍스트 대비가 AA를 만족합니다.
- 오류 코드마다 한국어 안내가 있습니다. 일부 업로드 실패와 삭제 실패는 화면을 가리지 않는 목록 안내로 보여 줍니다.
- 편집 충돌(revision)과 기능 설정에 따른 컨트롤 비활성화가 일관됩니다.

## 6. 재현 메모

- 화면 수집은 기존 브라우저 확인과 같은 방식입니다. 임시 저장소로 개발 서버를 띄우고, 세션 주소를 앱 내장 브라우저로 엽니다. 사용 중인 `.runtime/node/media`와 8080 포트는 쓰지 않습니다.
- 이미지 위 클릭은 `setPointerCapture` 때문에 실제 마우스 입력이 필요합니다(PROJECT_MAP 11절).
