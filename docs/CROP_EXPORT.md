# 선택 영역 자르기·PNG 저장

## 화면 동작과 저장 의미

우측 영역 자르기에서 영역 선택을 누르고 이미지 위를 드래그합니다.
선택 사각형은 회전·확대·이동과 함께 표시됩니다. X/Y/너비/높이를 정수 원본 픽셀로 정밀 조정할 수도 있습니다.
PNG로 저장하면 원본 해상도의 잘린 사본을 브라우저에서 다운로드합니다.
Esc 또는 취소로 선택을 지우며 파일/페이지 전환·권한 상실·세션 종료 시 선택과 진행 중 다운로드를 취소합니다.
메모·스탬프 배치 모드와 영역 선택 모드는 동시에 활성화하지 않습니다. 영역 선택에 진입하면 돋보기도 해제합니다.

저장 결과는 EXIF 방향을 보정한 정방향 원본 영역입니다.
화면 보기 회전은 선택 좌표를 계산하는 데 반영하지만 PNG를 추가로 회전시키지는 않습니다.
보기 밝기·메모·스탬프는 이 PNG에 합성하지 않습니다. UI에서도 저장 범위를 안내합니다.
이들을 포함한 편집 반출(EXPORT_EDITED)은 EDITED_EXPORT.md에 별도 구현했습니다. 업무 파일 사본 재등록·영구 보관·감사 이력은 후속 작업입니다.
현재 결과를 새 mediaId로 등록하지 않으며 기존 원본·메타데이터·주석은 변경하지 않습니다.

원본 크기·방향이 검증된 JDK JPEG/PNG/classic TIFF/GIF/BMP 페이지에 적용합니다.
외부 img2tile 미리보기의 원본 매핑이 불명확한 경우 열람만 허용하고 자르기를 비활성화합니다.
미리보기 픽셀을 원본으로 간주하거나 확대 저장하지 않습니다.

## API

POST /api/v1/media/{mediaId}/pages/{page}/crop

신뢰된 ViewerPrincipal, 최신 파일 VIEW 및 CROP_AND_SAVE 권한, 설치 crop-and-save 기능과 CSRF 헤더가 필요합니다.
먼저 현재 사용자 권한으로 해당 페이지 미리보기를 준비하고 페이지 API의 원본 좌표계/버전을 사용합니다.

~~~json
{
  "mediaVersion": "30000000-0000-4000-8000-000000000001",
  "coordinateSpaceId": "original:30000000-0000-4000-8000-000000000001:1:upright-v1",
  "x": 100,
  "y": 120,
  "width": 240,
  "height": 160
}
~~~

여섯 필드는 모두 필수입니다. 알 수 없는 필드는 거부합니다.
좌표/크기는 유한한 정수이며 x/y >= 0, width/height >= 1이어야 합니다.
영역 전체가 정방향 원본 페이지 안에 있어야 합니다. UI는 드래그 끝점을 바깥 픽셀 경계로 반올림합니다.
원본 경로·출력 경로·외부 URL·사용자/조직 식별자는 요청으로 받지 않습니다.

성공: 200 image/png, Cache-Control: no-store,
Content-Disposition: attachment; filename="imagegate-crop-p1.png".
Content-Length 및 X-Image-Width/X-Image-Height 헤더를 제공합니다.
원본 메타데이터를 복사하지 않은 PNG이며 원본 좌표 기준 너비/높이를 갖습니다.

| HTTP / code | 의미 |
| --- | --- |
| 400 / INVALID_EDIT 또는 입력 검증 오류 | 누락·분수·비유한 수·경계 밖·알 수 없는 필드 |
| 401 | 미인증 |
| 403 | CSRF 거부 또는 설치 기능 비활성 |
| 404 / MEDIA_NOT_FOUND | 미존재·조회/저장 권한 없음 |
| 409 / EDIT_NOT_READY | 페이지 미준비 또는 원본 좌표 미검증 |
| 409 / EDIT_CONFLICT | 원본 버전/좌표계/원본 SHA-256 불일치 |
| 413 / CROP_TOO_LARGE | 원본/출력 픽셀 또는 출력 바이트 상한 초과 |
| 413 / EDIT_REQUEST_TOO_LARGE | 변경 JSON 16KiB 초과 |
| 422 / INVALID_CROP | 원본 래스터 디코딩 불가 |
| 429 / CROP_BUSY | 저장 처리 슬롯 사용 중 |
| 503 / EDIT_STORAGE_UNAVAILABLE | 저장소/파일 처리 실패 |

내부 경로·스택·원본 내용은 오류 응답에 노출하지 않습니다.
원본 파일 크기나 카탈로그 자체가 손상된 경우 기존 미디어 저장소 검사가 먼저 503으로 거부할 수도 있습니다.

## 처리·속도·보안 경계

1. 파일 권한·페이지 상태·원본 버전/좌표계·입력/출력 한도를 확인합니다.
2. 별도 저장 슬롯을 대기 없이 확보합니다. 제한에 도달하면 429로 반환합니다.
3. 비공개 원본의 SHA-256을 검사하고 JDK 디코더의 크기·방향을 페이지 기하 정보와 다시 비교합니다.
4. 원본은 제한된 픽셀 수 안에서 디코딩합니다. 원본 정방향 전체 버퍼를 추가로 만들지 않고 선택 크기의 ARGB 목적 래스터에 직접 방향 보정·자르기를 적용합니다.
5. 상한이 있는 출력 스트림으로 PNG를 생성하고 저장 직전 파일 권한·버전을 다시 확인합니다.
6. 임시 PNG를 동기식 HTTP 출력으로 복사합니다. 느린 클라이언트와의 전송이 끝날 때까지 저장 슬롯을 유지합니다.
7. 성공·예외·연결 종료 시 알려진 임시 파일과 작업 폴더를 정리하고 슬롯을 반환합니다.

원본/PNG 전체를 byte[] 응답에 넣지 않습니다.
PNG 인코더는 제한된 래스터와 인코딩 캐시를 사용할 수 있으므로 JVM 메모리가 0인 스트리밍은 아닙니다.
프리뷰 워커와 별도 저장 슬롯을 사용합니다. 전체 소스 디코딩, 동기식 요청의 CPU 비용과 디코더 강제 시간 제한은 잔여 성능 검증 대상입니다.
현재 실제 업무 자료·동시 사용자 P95 측정과 실제 SSO 종단간 시험은 수행하지 않았습니다.

## 설치 YAML

~~~yaml
imagegate:
  features:
    image:
      crop-and-save: true
  crop:
    max-source-pixels: 16000000
    max-output-pixels: 8000000
    max-output-bytes: 16777216
    max-concurrent-jobs: 1
~~~

원본 픽셀 최대 40,000,000, 출력 최대 8,000,000픽셀·16MiB, 동시 저장 최대 2로 검증합니다.
기본 원본 픽셀 상한은 16,000,000이며 페이지 미리보기의 독립적인 픽셀 정책도 먼저 충족해야 합니다.
이 상한과 저장/전송 슬롯은 편집 합성 반출도 공유합니다. 설치 후 재시작이 필요합니다. bootstrap limits에 maxCropOutputPixels/maxCropOutputBytes를 제공합니다.

작업 폴더는 설정된 imagegate.storage.converted-directory/crop-work-v1/crop-*입니다.
사용자 지정 파일명/경로를 사용하지 않으며 정적 웹 경로로 공개하지 않습니다.
서비스 강제 종료나 OS 파일 잠금으로 정리하지 못한 작업은 서비스 중지 후 이 전용 폴더 안에서 관리자가 확인해 정리합니다.
장기 다운로드 보관소·자동 퇴거·분산 저장 작업 큐가 아닙니다.
ImageMagick·FFmpeg·새 런타임 라이브러리를 추가하지 않았습니다.

## 검증

- API: 실제 원본 픽셀 비교·원본 보존·임시 파일 정리·입력 경계/분수/본문 상한·권한/CSRF·버전/좌표계·원본 SHA-256 변경 차단.
- 래스터: PNG EXIF 8방향의 독립 색상 기준 비교, TIFF 2페이지 방향, 원본 픽셀/출력 바이트 한도·기하 불일치.
- 서비스: 느린 다운로드 중 슬롯 유지·클라이언트 예외 후 슬롯 반환·저장 직전 권한 회수·미검증 외부 원본 매핑 거부.
- 설치: 정책을 끈 소유자의 직접 API 호출 차단, YAML 상한 검증.
- 브라우저: 회전/확대 선택 좌표·정수 조절·실제 PNG 다운로드·CSRF·409 충돌 안내·취소·늦은 응답 무시·읽기 전용·좌표 미확인 차단.
- 브라우저는 실제 UI와 합성 API/PNG를 사용합니다. 원본 픽셀 정확성은 별도 Java 테스트로 검증합니다.
