# 운영 감사 로그

설정: imagegate.audit.enabled(기본 true). 설치 예제의 logging.file.path로 디렉터리를 지정합니다. 기본은 ./.runtime/logs이며 변경 후 재시작합니다. 인증/파일 권한을 대체하지 않습니다.

## 기록 범위

- 미디어 등록, 메모/스탬프 생성·수정·삭제, undo/redo, 개인 스탬프 업로드, crop/편집 PNG 반출 요청.
- 명시적인 preview/playback 준비 요청. 요청 접수 응답과 비동기 작업 결과는 서로 다른 사건입니다.
- 미리보기·재생 변환 작업 실패. 작업을 요청한 신뢰 사용자와 미디어 UUID, 제한된 오류 코드만 기록합니다.
- 위 요청의 인증/CSRF/권한 거절 및 충돌/입력 오류 응답도 기록합니다. 인증 문맥 안에서 CSRF/권한 필터보다 앞에 위치하며 서블릿 필터 중복 등록을 차단합니다.

GET/HEAD 조회, 썸네일, 동영상 Range, 원본 파일 본문, 임의의 URL이나 잘못된 라우트 전체를 감사 대상으로 수집하지 않습니다. 인증 필터보다 앞의 방화벽/컨테이너 거절, 서버 시작 전 실패도 범위 밖입니다.

## 형식과 의미

UTC 시간 + 고정 key=value, schema=1. 서버가 생성하는 event UUID, enum action, 신뢰 principal의 tenant/actor, 미디어 UUID, 1~10000 페이지, HTTP status, outcome, 오류 code, durationMs를 사용합니다. 비동기 실패 status=0, outcome=JOB_FAILED입니다. actor는 없으면 '-'이며 헤더/파라미터로 사용자를 추측하지 않습니다. 페이지/미디어/코드는 허용 패턴에 맞지 않으면 '-' 또는 UNKNOWN입니다.

HTTP_RESPONSE는 동기 요청 체인이 반환한 상태입니다. INTERRUPTED는 예외가 빠져나간 경우이며, 이미 헤더가 전송되었다면 status=200일 수도 있습니다. HTTP 2xx는 사용자의 저장 완료, 영구 저장 트랜잭션 증명 또는 재생 변환 완료를 뜻하지 않습니다. 등록 후 후속 처리 오류는 원본 저장 이후에도 발생할 수 있고, 응답 전송 오류와 편집 디스크 커밋도 독립적입니다. 이벤트 UUID는 개별 기록의 식별자이며 재시도 중복 제거/요청 간 추적 ID가 아닙니다.

파일명, 물리 경로, 요청/응답 본문, 메모 텍스트, 스탬프 이미지, 헤더/쿼리, 인증 토큰, IP, 원시 예외/스택/외부 명령 출력은 감사 로그에 쓰지 않습니다. 사용자 식별자는 운영 추적에 필요한 개인정보일 수 있으므로 로그 접근을 제한해야 합니다.

## 파일 운영과 한계

추가 의존성 없이 기존 SLF4J/Logback을 사용합니다. audit.log는 일반 콘솔 로그와 분리하며 동기 기록합니다. 변경 요청당 짧은 한 줄이고 대량 조회/재생 경로에는 쓰기를 추가하지 않습니다. 로그 디스크 지연은 변경 응답 지연에 영향을 줄 수 있습니다.

일별/10MB 크기 회전, gzip, 보관 30일/아카이브 합계 1GB 정리 목표입니다. 활성 파일은 합계 상한 밖이고 정리는 회전 시점에 이루어지므로 디스크 하드 쿼터가 아닙니다. 설정을 false로 하면 감사 이벤트 발행을 멈추지만 Logback 초기화로 빈 파일/디렉터리는 만들어질 수 있습니다. 일반 진단 로그는 계속 유지됩니다.

서버 인스턴스별 별도 로그 경로를 사용하고 여러 JVM이 같은 회전 파일을 공유하지 않게 합니다. 운영 계정만 디렉터리에 읽기/쓰기가 가능하도록 OS ACL을 설정하고 웹 정적 경로/미디어 저장소와 분리하세요. 모듈/실제 자료/로그를 저장소에 커밋하지 않습니다. 디스크 부족·쓰기 오류는 Logback 진단으로 확인해야 하며 업무 처리를 롤백하거나 감사 기록 보장을 위해 차단하지 않습니다. 이 로그는 변조 방지, WORM, 전자서명, 법적 증적 보존 또는 원격 수집 보장을 제공하지 않습니다. 그런 요건은 별도의 운영 수집·보존 체계와 검증이 필요합니다.

## 검증

감사 필터 단위 테스트와 실제 Spring Security/MockMvc 테스트로 개인정보 제외, 본문 비소비, 조회/비활성화 제외, 전송 예외 전파, 컨텍스트 경로, 기능별 action, 제한 코드, CSRF 거절 단일 기록, 익명 헤더 위조 무시, 정상 등록 UUID를 확인합니다. 설치 설정 바인딩/알 수 없는 옵션 거절도 검증합니다. 파일 회전은 Logback의 정책을 사용하며 이 테스트가 실 운영 디스크 장애/장기 보관을 재현하지는 않습니다.

이번 변경 검증: JDK 21에서 build -Pimg2tileIntegration -PffmpegIntegration 성공. Java 테스트 총 239개, 실패 0·오류 0·건너뜀 0개. UI 변경이 없어 브라우저 시나리오는 이번 단계에서 재실행하지 않았습니다. 설치 ZIP은 생성하지 않았습니다.
