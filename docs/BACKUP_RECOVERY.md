# 백업·복구 운영 절차

이 문서는 현재 로컬 파일 저장소의 **서비스 중지 상태 백업·다른 경로 복원** 절차입니다. 자동 백업 스케줄러나 운영 복구 CLI는 구현하지 않았습니다. 저장소 회복 검증은 합성 자료로 수행하며 실제 설치 데이터를 복사·삭제하지 않습니다. 설치 ZIP 생성 단계와 별개입니다.

## 백업 단위

설치 YAML의 imagegate.storage.root와 각 directory 값을 결합한 **실제 절대 경로**를 운영자가 먼저 기록합니다. directory가 절대 경로이면 root 밖에 있을 수 있으므로 root 한 개만 복사해서는 안 됩니다. 현재 설정은 네 저장 경로의 중첩을 거절합니다.

| 대상 | 백업에 포함할 데이터 | 복구 시 주의점 |
| --- | --- | --- |
| storage.originals-directory | 모든 tenant-* 아래 미디어 UUID 디렉터리의 metadata.properties와 original.* | mediaId, tenantId, ownerId, version, sha256와 바이너리를 한 세트로 보존. 파일명만으로 다시 등록하지 않음 |
| storage.annotations-directory | tenant/mediaId/version/page-N.properties 전체 | 주석 내용·스탬프 소유자 참조·좌표계·revision 및 항목이 0개인 삭제 스냅샷도 보존 |
| storage.stamps-directory | tenant/user/스탬프 UUID 아래 metadata.properties, stamp.png, preview.png | 주석에서 다른 소유자의 스탬프를 참조할 수 있으므로 일부 사용자만 골라 복사하지 않음 |
| config/imagegate.yml 및 외부 인증/ACL 설정 | 설치 기능·상한·경로 매핑·SSO/ACL 연동 버전 | 비밀정보는 별도 비밀 저장소에서 보호. 실제 파일을 소스 저장소/공개 아카이브에 넣지 않음 |
| audit.log 및 회전 파일 | 설치 정책이 정한 감사 기록 | 애플리케이션 데이터와 별도 보존/접근 권한. 현재 로그는 트랜잭션 원장이나 변조 방지 저장소가 아님 |
| 애플리케이션·JDK·변환 모듈 식별 | 배포 버전, 설정 버전, 바이너리 해시, 외부 DLL/리소스·실행 환경 식별 | 실행 파일은 소스 저장소가 아닌 승인된 배포 저장소에서 확보. 특히 변환 결과 재생성에 필요한 모듈/레시피 버전을 기록 |

converted-directory의 previews-v1/playback-v1은 재생성 가능한 캐시입니다. 기본 복구 시 비어 있는 전용 converted 경로를 사용하면 오래된 상태·중단 작업·손상된 결과를 승계하지 않습니다. 첫 조회의 변환 시간/부하를 감안해 인수 후 권한 있는 요청으로 필요한 파일부터 준비합니다. 캐시를 함께 백업하는 정책이면 반드시 같은 중지 시점의 전체 캐시를 별도로 기록하고, 새 캐시와 섞지 않습니다. 단순 GET이 항상 변환 접수를 수행하는 것은 아니며 기존의 명시적 준비/재시도 API를 사용합니다.

메모리의 로그인/CSRF 세션, 뷰어 세션, 큐 및 undo/redo 기록은 복구 대상이 아닙니다. 재로그인·새 뷰어 세션이 필요하며, 저장된 최종 주석과 revision이 복구됩니다. crop 다운로드 임시 작업·중단 upload/work 파일을 업무 원본으로 취급하지 않습니다.

## 백업 실행

1. 운영 점검 창을 열고 프록시/업무 시스템에서 신규 등록·편집·재생/변환 요청 유입을 중단합니다. 다중 인스턴스가 있으면 같은 저장소를 사용하는 모든 인스턴스를 대상으로 합니다.
2. 진행 중 요청을 종료하고 ImageGate를 정상 중지합니다. img2tile·FFmpeg 및 남은 하위 프로세스도 종료됐는지 확인합니다. quota 활성 원본 writer는 기존 .quota-writer.lock을 보유하지만 quota 비활성 writer와 외부 작업까지 이 잠금으로 중지를 보장할 수 없으며, 편집/캐시 잠금만으로 전체 백업 일관성도 보장하지 않습니다. 잠금 파일 존재/삭제 여부로 프로세스 중지를 판단하지 않습니다.
3. 서비스 계정 전용 원본/주석/스탬프와 필요한 운영 설정·감사 기록을 같은 중지 시점으로 확보합니다. 중지 상태를 유지하는 동안 승인된 백업 제품이나 파일시스템 스냅샷/복사를 사용합니다. 서로 다른 볼륨도 모두 확보될 때까지 writer를 시작하지 않습니다. 실행 중 파일별 복사나 주석만 별도 시점 복사는 현재 지원하는 일관성 모델이 아닙니다.
4. 백업 식별자·UTC 시각·애플리케이션/모듈/설정 버전·원래 경로→백업 경로 매핑·파일 수·바이트 합계와 각 파일의 상대 경로/크기/SHA-256 목록을 만듭니다. 링크/정션을 따라 외부 데이터가 포함되지 않게 하고, 알 수 없는 경계가 있으면 백업을 불완전으로 분류해 검토합니다. manifest는 원본 이름/tenant 등 민감정보를 포함할 수 있어 데이터와 같은 보호가 필요합니다. 해시 목록은 변조 탐지를 위해 승인된 백업 시스템의 서명/불변 저장/접근 통제 등으로 별도 보호합니다.
5. 복사본의 파일 목록과 해시를 원본 측 목록에 대조하고 백업 제품의 완료/검증 결과를 남깁니다. 실패·누락이 있으면 해당 백업을 복구 가능한 최신본으로 승격하지 않습니다. 암호화·접근 권한·별도 장애 영역 저장·보존 기간은 설치 운영 정책으로 적용합니다.
6. 검증한 백업 식별자를 기록하고 서비스를 재개합니다. OS ACL·암호화 키·인증/ACL 설정은 데이터 해시 목록만으로 복구되지 않으므로 별도 보관·복구 절차도 함께 점검합니다.

현재 프로젝트에는 manifest 생성/서명 도구가 없습니다. 아래 자동 테스트의 복사 보조 코드는 TempDir 합성 자료 전용이며 운영 백업 기능이 아닙니다.

## 격리 경로에 복원

1. 운영 트래픽이 없는 복구 환경을 준비합니다. 원래 저장소를 덮어쓰거나 최신 백업을 수정하지 않고 **새 빈 절대 경로**에 복원합니다. 점검 전에는 업로드/편집/변환 writer와 자동 정리 작업을 시작하지 않습니다.
2. 백업 manifest/서명 등 출처를 검증하고, 원본·주석·스탬프 전체의 파일 목록·크기·SHA-256을 대조합니다. 같은 크기의 내용 변경은 크기만으로 발견되지 않으므로 전체 해시 검증이 필요합니다. 파일 권한·서비스 계정 소유·링크/정션/공개 웹 경로 노출도 확인합니다.
3. 승인된 동일 버전 JDK/애플리케이션과 변환 모듈을 설치합니다. 임의로 저장 형식이나 미디어 UUID/version/owner/tenant/주석 revision을 수정하지 않습니다. 버전 업그레이드는 원래 버전으로 복구가 확인된 뒤 별도 작업으로 진행합니다.
4. 설치 YAML의 네 저장 경로를 복원 경로로 매핑합니다. originals/annotations/stamps는 같은 백업 세트를 사용합니다. converted는 기본적으로 새 빈 전용 경로입니다. 임시 설정/백업을 소스 저장소에 넣지 않습니다. 로그 경로·용량 상한·기능 사용 여부·외부 실행 경로와 해시도 확인합니다.
5. 실제 업무 SSO/ACL·tenant/user 식별을 복원 환경에 연결합니다. 백업의 소유자 식별자와 현재 로그인 식별자가 일치해야 하며, 데이터가 복구됐다는 이유로 공개 접근이나 인증 우회를 켜지 않습니다. 실제 SSO/공유 ACL 연동은 현재 프로젝트의 잔여 과제입니다.
6. 격리 환경에서 서비스를 시작하고 다음 인수 항목을 검사합니다. 이상이 있으면 트래픽을 열지 말고 원본 백업과 비교합니다. 미확인 파일을 자동 삭제하거나 재등록하여 문제를 가리지 않습니다.

## 복구 인수 항목

- 원본: tenant/mediaId/version/owner/이름·종류·크기·원본 SHA-256 일치, 원본 다운로드 내용 일치. 카탈로그 조회의 크기 검사만을 전체 무결성 검사로 간주하지 않음.
- 주석: 파일 버전·페이지·좌표계와 메모 내용/위치/크기/스탬프 ID·소유자 참조 일치, 삭제된 페이지의 빈 스냅샷과 revision 유지. 오래된 revision 갱신은 충돌로 거절.
- 스탬프: 개인 목록·미리보기·참조된 전체 해상도 PNG와 합성 반출 확인. 개인 스탬프가 누락돼도 주석 문서 자체를 읽을 수 있으므로 반드시 참조 해석/렌더링까지 확인.
- 누락 방지: 주석 파일이 없으면 현재 저장소는 revision0의 빈 문서로 읽을 수 있습니다. 읽기 성공이나 화면에 메모가 없다는 사실만으로 복구 성공을 판정하지 않고 manifest와 원본 백업에 대조합니다. 항목 수0/revision>0의 스냅샷도 생략하지 않습니다.
- 보안: 실제 인증을 통한 소유자 허용·타 사용자/조직 거절, 설치 기능 정책, CSRF, 원본/썸네일/재생 Range/합성 반출 접근 검사. 저장소 계층만으로 HTTP ACL 검증을 대체하지 않음.
- 재생성: 이미지/썸네일, MP4/MPEG·MP3/WAV를 필요한 권한으로 준비하고 표시/재생·seek·Range를 확인. 캐시가 비어 있으면 첫 준비가 느릴 수 있음.
- 운영: 감사 로그 수집/회전, 디스크 여유 공간, 모듈 제한 시간·동시성, 실패 후 명시적 재시도 및 기동/중지 확인. RPO는 완료한 백업 시점, RTO는 복사/해시/기동/재생성/실 SSO 인수 시간을 포함해 운영 리허설에서 측정.

실제 서비스 전환은 이 인수와 업무 담당자의 복구 범위 확인 후 진행합니다. 복원본에서 신규 쓰기가 발생한 뒤 이전 환경으로 돌아갈 때에는 신규 데이터 조정 정책이 필요하며 양쪽 writer를 동시에 열지 않습니다.

## 자동 리허설 범위

maintenance/repository/RecoveryRehearsalTests는 작은 합성 PNG를 실제 LocalMediaStore에 등록하고, 실제 StampStore/AnnotationStore로 메모·스탬프·빈 페이지 revision을 저장한 뒤 모든 writer를 닫습니다. 별도의 백업 경로와 복원 경로로 복사하고 새 저장소 객체로 재개방하여 다음 항목을 검증합니다.

1. 원본 바이트/SHA-256·카탈로그 식별자·주석·스탬프 래스터·revision 충돌·tenant/개인 목록 구분 유지, 복원본 갱신이 원본 자료를 변경하지 않음.
2. 참조된 stamp.png 누락 시 래스터 복구 거절.
3. 원본 metadata.properties 누락 시 유효 카탈로그로 반환하지 않음.
4. writer 재개방 전에 원본 무결성·편집 참조 점검을 실행하고 정상 원본 1개/주석 페이지 2개/스탬프 1개 및 부분 보고가 아님을 확인. 점검 전후 전체 파일/디렉터리 목록·바이트 해시 동일성 확인.
5. 동일 크기 원본 변조는 SHA-256 점검에서 거절, 원본 버전이 다른 혼합 세트는 편집 참조 점검에서 거절. 누락 원본 카탈로그/스탬프도 오프라인 검사에 연결.
6. 빈 주석 스냅샷 누락·동일 크기 스탬프 PNG 변조는 구조/참조 검사만으로 발견되지 않는 경우임을 확인하고 독립 파일 목록/해시 대조로 발견.
7. 원본/참조 검사 상한 도달은 완료로 인정하지 않음. 합성 복사 보조 코드가 기존 목적지·자기 자신·하위/상위 경로 복원을 쓰기 전에 거절. 복원본 수정 후 원본과 백업의 전체 목록/바이트 보존 확인.

테스트의 manifest는 합성 원본에서 만든 메모리 내 파일/디렉터리 목록·크기·SHA-256 맵이며 복원 경로 밖에 유지합니다. 운영 manifest 생성/서명/보호 도구를 구현한 것은 아닙니다. 실제 복구 인수는 **보호된 외부 manifest 대조 + 원본 무결성 완료 + 편집 참조 검사 완료 + 실제 인증/렌더링/재생 인수**를 모두 충족해야 합니다. 두 점검 명령이 종료0이어도 전체 파일 누락이나 이미지 본문 변경이 없는 완전한 백업임을 보증하지 않습니다. 서비스 writer를 열기 전에 이 오프라인 검사를 수행하세요.

이는 저장 형식 간 관계를 검사하는 회귀 테스트입니다. 운영 백업 제품, OS ACL/암호화 키, 외부 manifest 검증, 실제 SSO/HTTP 권한, 실제 업무 자료/영상·대규모 디스크 복원·RPO/RTO를 검증한 결과로 해석하지 않습니다. 이 항목들은 배포 환경에서 별도 리허설이 필요합니다. 자동 캐시 잔재 정리와 구분하며 OFFLINE_MAINTENANCE.md를 참고하세요.

개발 검증 명령(설치 ZIP을 만들지 않음):

~~~powershell
.\gradlew.bat --no-daemon --console=plain test --tests "*RecoveryRehearsalTests" -Pimg2tileIntegration
.\gradlew.bat --no-daemon --console=plain build -Pimg2tileIntegration -PffmpegIntegration
~~~
