# 사용성 확인 (리뉴얼 5단계)

2026-11-19 작성. 4단계까지 반영한 화면(`fb2c16f` 이후)을 실제 사람이 쓸 수 있는지 확인하는 과업 테스트 진행안입니다. 점검 항목 ID(U·A·M)는 [UX_HEURISTIC_REVIEW.md](UX_HEURISTIC_REVIEW.md)를 따릅니다.

구성:
- 1~6절: 진행자가 그대로 따라 하는 진행안
- 7절: AI 파일럿 결과 — 진행안과 환경을 미리 돌려 본 것이며, 실제 사용자 결과를 대신하지 않습니다.

## 1. 목적과 판단 기준

4단계에서 고친 심각도 3 항목이 처음 쓰는 사람에게도 해결됐는지 봅니다.

| 확인할 것 | 관련 과업 | 관련 ID |
| --- | --- | --- |
| 빈 화면에서 파일을 열 수 있다 | T1 | U17 |
| 아이콘만 보고 확대·맞춤을 찾는다 | T2 | U3, U14 |
| 메모·스탬프를 오류 화면 없이 단다 | T3, T4 | U13, U10 |
| 실수를 되돌린다 | T5 | U5, H3 |
| 저장 버튼을 찾고 저장됐음을 안다 | T6, T7 | U15, U2 |
| 키보드만으로 메모를 옮긴다(선택) | T9 | A1, U17 |
| 좁은 화면에서 파일을 바꾸고 확대한다(선택) | T10 | M1, M2 |

판단 기준(참가자 5명 기준):
- 과업별 **도움 없이 성공 4명 이상**이면 통과입니다.
- **2명 이상이 실패하거나 같은 곳에서 막히면** 심각도 3으로 기록하고 다음 개선 대상에 넣습니다.
- 과업 직후 쉬움 점수(SEQ, 1~7) 평균이 **5.5 미만**이면 원인을 따로 적습니다.

## 2. 참가자와 환경

- **인원:** 3~5명. 이 뷰어를 써 본 적 없는 사람을 우선하고, 1명은 평소 키보드를 많이 쓰는 사람이면 좋습니다.
- **시간:** 1인 20~25분(과업 15분 + 질문 5분).
- **기기:** 1440×900 이상 PC 브라우저(Chrome·Edge). T10은 같은 브라우저의 개발자 도구 기기 모드(375×812, 터치 에뮬레이션)로 합니다. 마우스로 하는 핀치는 실제 손가락과 다르므로 T10 결과는 참고로만 씁니다.
- **테스트 서버:** 실제 미디어 저장소(`.runtime/node/media`)와 8080 서버를 쓰지 않도록 전용 스크립트를 씁니다.

```powershell
$env:PATH = "$PWD\.tools\runtimes\node-24.22.1;$env:PATH"
node scripts/usability-test-server.mjs --port 18200
```

  - 출력된 `Usability test viewer` 주소를 같은 PC의 브라우저로 엽니다. 이 스크립트는 `127.0.0.1`에서만 접속을 받으므로 다른 PC나 휴대폰에서는 열 수 없습니다.
  - `Sample files` 폴더를 탐색기로 열어 둡니다. 들어 있는 파일은 `document.png`(문서 모양, 오른쪽 아래 빨간 상자), `stamp-check.png`(투명 스탬프), `two-pages.gif`(2페이지)입니다. 이 PC에 재생 표본이 있으면 `input.mp4`, `input.wav`도 들어 있습니다.
  - 참가자마다 서버를 **터미널에서 Ctrl+C로 끄고 다시 시작**합니다. 그러면 빈 상태에서 시작하고 임시 폴더도 지워집니다. 작업 관리자 등으로 프로세스를 강제 종료하면 임시 폴더(`%TEMP%\siv-usability-*`)가 남으니 직접 지웁니다. 결과를 보존하려면 `--keep`을 붙입니다.
- 브라우저 다운로드 폴더를 미리 비워 두면 T6·T7 결과 파일을 확인하기 쉽습니다.

## 3. 진행 대본

1. "이 화면을 평가하는 것이지 당신을 평가하는 것이 아닙니다. 막히면 그건 화면 문제입니다."
2. "하면서 생각나는 것을 소리 내어 말해 주세요. 찾는 것, 기대한 것, 놀란 것 모두요."
3. 과업 카드를 한 장씩 보여 주고 읽게 합니다. 진행자는 **버튼 이름이나 위치를 말하지 않습니다.**
4. 3분이 지나도 진행이 없거나 참가자가 포기하면 도움을 주고 결과를 "도움 받아 성공"으로 적습니다.
5. 과업마다 끝나면 "이 과업은 쉬웠다"에 1(매우 어려움)~7(매우 쉬움)로 답하게 합니다.

## 7. AI 파일럿 결과 (2026-11-19)

진행안, 표본, 테스트 서버가 제대로 동작하는지 보려고 AI가 먼저 과업을 해 봤습니다. AI는 화면 구조를 이미 알고 있어서 **시간·성공률은 의미가 없고**, 처음 쓰는 사람이 막힐 만한 곳을 찾는 인지적 워크스루로만 봅니다.

- **환경:** `scripts/usability-test-server.mjs`(포트 18200, 빈 임시 저장소), 앱 내장 브라우저 1440×900 다크
- **과업 수행:** T1~T7을 새로 했습니다. 메모·스탬프·자르기·이동은 실제 마우스 입력으로 했습니다. 파일 끌어다 놓기와 스탬프 업로드는 탐색기 창을 쓸 수 없어서, 같은 모양으로 만든 파일을 스크립트로 넣었습니다.
- **수행하지 않은 과업:** T8~T10은 4-5 회귀 확인에서 같은 동작(GIF 페이지·삭제 확인 창·키보드 이동·모바일 시트·핀치)을 이미 확인해서 다시 하지 않았습니다.

### 7.1 파일럿 중 찾아서 고친 결함

| 결함 | 원인 | 수정 | 확인 |
| --- | --- | --- | --- |
