# 원본 무결성 점검

서버를 시작하지 않는 읽기 전용 오프라인 명령입니다. 원본 metadata.properties의 등록 당시 SHA-256/크기를 실제 original.*와 대조합니다. 파일을 수정·복구·삭제하거나 변환 프로그램을 실행하지 않습니다. 설치 YAML/환경 경로를 자동으로 읽지 않으며 명시적인 원본 절대 경로를 요구합니다.

## 실행

ImageGate와 같은 저장소를 사용하는 모든 writer/외부 작업을 중지한 뒤 실행합니다. quota 활성 원본 writer는 .quota-writer.lock을 보유합니다. 이 명령은 기존 marker만 READ/shared로 잠그고 점검 전체에서 유지하며, 실제 writer가 보유 중이면 종료4로 거절합니다. quota 비활성 writer나 외부 프로세스는 이 잠금을 사용하지 않을 수 있으므로 --workers-stopped는 여전히 모든 writer에 대한 운영자의 중지 확인입니다. 프로세스를 자동 중지하거나 잠금 파일을 생성/삭제하지 않습니다.

~~~powershell
# 개발 빌드 JAR. 설치 ZIP을 생성할 필요가 없습니다.
java -jar ./build/libs/imagegate-0.1.0-SNAPSHOT.jar --maintenance --verify-originals --help
java -jar ./build/libs/imagegate-0.1.0-SNAPSHOT.jar --maintenance --verify-originals --originals-root D:/ImageGateData/originals --workers-stopped
~~~

--maintenance는 첫 인자, --verify-originals는 그 바로 다음 인자여야 합니다. --apply는 지원하지 않습니다. 점검 출력이 필요하면 보호된 운영 보고서 경로로 표준 출력을 리디렉션합니다. 원본 이름과 경로는 출력하지 않지만 미디어 ID도 내부 식별자이므로 보고서를 공개하지 않습니다.

| 옵션 | 기본값 / 허용 범위 |
| --- | --- |
| --originals-root | 필수. 정규화된 기존 절대 경로, 원본 루트만 지정 |
| --workers-stopped | 필수. 서비스/동일 저장소 writer 중지 확인 |
| --max-files | 1000 / 1~10000. 정상/오류를 합친 결과 항목 수 상한 |
| --max-entries | 10000 / 1~100000. tenant/미디어/그 안의 항목 열거 상한 |
| --max-bytes | 1073741824(1GiB) / 1~1099511627776(1TiB). 원본 SHA-256에 읽을 바이트 상한 |

경로·상한·중지 확인은 CLI 옵션으로만 받습니다. 서버 기능 활성화/YAML과 분리한 명시적 관리 작업이며 사용자 권한을 대신하지 않습니다. 경로가 없으면 디렉터리나 잠금 파일을 생성하지 않습니다.

## 검사 범위

- tenant-64자리 소문자 SHA-256 / 미디어 소문자 UUID / metadata.properties, original.확장자의 고정 깊이만 열거합니다. 전체 트리 재귀 탐색은 하지 않습니다.
- 루트·tenant·미디어·파일의 canonical 경로 및 NOFOLLOW 속성을 확인합니다. 심볼릭 링크/Windows 정션·일반 파일이 아닌 객체는 따라가지 않습니다. 모르는 파일/디렉터리, 중단 .upload-*도 문제 항목으로 보고하고 보존합니다.
- 메타데이터는 파일당 최대16KiB로 읽으며 알려진 필드 집합, 미디어 ID/버전 UUID, tenant/user 식별 형식, tenant 폴더 해시, 원본 파일명 경계·크기·기록 SHA-256·생성 시각을 확인합니다. 미래 저장 형식의 필드가 추가되면 자동으로 무시하지 않고 오류로 보고합니다.
- 원본은32KiB 버퍼로 전체 SHA-256을 계산합니다. 등록 때 사용한 헤더 분류와 저장 확장자·종류·MIME도 대조합니다. 이미지 전체 디코딩·동영상/음성 코덱 검증이나 악성 파일 탐지는 아닙니다.
- 해시 계산 전후에 원본·메타데이터·상위 경로 속성과 메타데이터 바이트를 재확인합니다. 종료 직전에는 방문한 정상 tenant 경계와 검증 완료 원본/미디어 경로/카탈로그의 속성을 전체 재대조하고, 카탈로그 바이트의 SHA-256도 다시 읽어 대조합니다. 앞 항목의 VERIFIED 판정 이후 뒤 항목을 검사하는 동안 바뀐 경우도 성공 보고서를 반환하지 않습니다. fileKey를 제공하는 파일시스템은 해당 식별자도 비교하며 Windows 등에서는 생성/수정 시각·크기와 전체 원본 해시를 함께 사용합니다. 변경이 관찰되면 정상 결과로 처리하지 않습니다.

max-bytes는 원본 해시에 대한 상한입니다. 메타데이터·디렉터리 IO는 포함하지 않으며, 성장한 파일의 끝 검사를 위해 파일당 최대1바이트를 추가로 확인할 수 있습니다. 다음 파일 전체가 남은 바이트 상한에 들어오지 않으면 부분 해시를 정상 판정하지 않고 그 지점에서 부분 보고로 끝냅니다. 크기가1TiB를 초과하는 카탈로그는 현재 지원 범위 밖입니다. 파일 수/총 메타데이터 크기도 별도 열거/결과 상한으로 제한합니다.

## 보고서와 종료 코드

schemaVersion=1, generatedAt(UTC), scanned(열거 수), hashedBytes(원본 해시에 읽은 바이트), limitReached, verified, issues, items를 JSON으로 출력합니다. items는 mediaId(UUID 또는 식별 전 오류의 null)와 outcome만 포함합니다. 파일명·tenant/user·절대 경로·내용·기록/계산 해시·원시 오류 메시지는 출력하지 않습니다.

| outcome | 의미 |
| --- | --- |
| VERIFIED | 이번 점검에서 등록 카탈로그의 크기/전체 해시/헤더 분류가 일치 |
| CHECKSUM_MISMATCH | 크기는 같아도 전체 SHA-256이 기록과 다름 |
| SIZE_MISMATCH | 원본 크기가 기록과 다름 |
| INVALID_OR_UNREADABLE | 카탈로그/경계/참조/형식이 유효하지 않거나 읽을 수 없음 |
| UNEXPECTED_ENTRY | 고정 저장 구조에 없는 항목 존재. 내용은 읽거나 삭제하지 않음 |
| CHANGED_DURING_SCAN | 해시 전후 파일/메타데이터/경로 변경 관찰 |

종료0은 **이번 제한 범위에 문제를 발견하지 못함**, 2는 인자 오류, 3은 문제 또는 상한 도달에 따른 부분 점검, 4는 기존 quota writer 잠금 사용 중(STORAGE_IN_USE), 5는 루트/잠금 marker/권한/IO·종료 재검사 변경 등으로 점검을 완료할 수 없음을 뜻합니다. 0에서도 verified=0이면 점검된 원본이 없습니다. 루트 전체 오류·잘못된 marker(비어 있지 않음/별칭/특수 파일 등)·marker 출현/변경·이미 검증한 항목의 종료 재검사 변경은 고정된 INTEGRITY_UNAVAILABLE 오류만 출력하며 JSON/이전 VERIFIED를 성공 보고서로 반환하지 않습니다. 개별 파일 해시 전후에 직접 발견한 CHANGED_DURING_SCAN은 기존대로 문제 항목/종료3입니다.

열거 순서는 고정하지 않습니다. 상한으로 끝났다면 재실행이 다음 항목부터 이어진다는 보장이 없으며 현재 재개 커서/tenant별 선택 기능은 없습니다. 전체 점검이 필요한 경우 실제 규모에 맞는 명시적 상한으로 점검 창을 잡거나 승인된 백업 제품의 전체 파일 검증을 함께 사용합니다. IO 영향은 오프라인 점검 시간과 스토리지 처리량에 따라 달라집니다.

## 기존 잠금과 종료 재검사

.quota-writer.lock이 없으면 새 marker를 만들지 않으며, 종료 시에도 없는 상태인지 확인합니다. 존재하면 빈 canonical 일반 파일만 허용하고 READ/shared FileLock을 유지합니다. 같은 JVM의 겹치는 writer와 별도 JVM의 실제 OS 잠금 모두 사용 중으로 처리합니다. 성공/문제/부분 보고·예외의 모든 종료 경로에서 소유한 잠금만 해제합니다. 기존 파일은 보존합니다.

루트 속성은 marker 획득 전부터 종료까지 유지해 경로 교체도 검사합니다. 정상 tenant 및 검증된 미디어/카탈로그/원본의 속성 캐시와 카탈로그 SHA-256(고정 크기)만 보관하며 전체 카탈로그 본문/원본 바이트를 축적하지 않습니다. 캐시 항목은 기존 열거/결과 상한으로 제한됩니다. 종료 재검사와 marker 검사는 scanned/hashedBytes에 더하지 않습니다. 카탈로그 종료 재읽기(파일당16 KiB 제한)는 max-bytes 밖의 추가 I/O입니다.

[복구 통합 점검](RECOVERY_ACCEPTANCE.md)은 자신이 보유한 ReadOnlyStorageScope의 원본 root를 검증한 뒤 같은 검사 코어를 호출합니다. 원본 marker를 다시 획득해 중복 FileLock을 만드는 우회/자동 재시도는 추가하지 않습니다. 닫힌 범위·다른 원본 root·다른 스레드의 범위는 거절합니다.

## 보장하지 않는 범위

등록 카탈로그와 원본이 서로 일치하는지 검사하는 도구입니다. 공격자가 원본과 메타데이터 SHA-256을 함께 바꾸면 신뢰된 외부 기준선 없이는 탐지하지 못합니다. 전체 미디어 디렉터리가 삭제된 경우나 원래부터 비어 있는 루트는 이 도구만으로 누락을 알아낼 수 없습니다. 백업 제품의 보호된 manifest/파일 수/별도 해시/서명과 대조해야 합니다. 주석·스탬프 누락/참조 무결성도 별도 복구 인수 항목입니다.

서비스 계정만 쓰는 전용 저장소와 중지한 writer가 전제입니다. 점검 중 다른 프로세스가 같은 계정으로 파일/상위 경로를 바꾸면 Java 경로 점검과 실제 열기 사이 경쟁을 완전히 배제할 수 없습니다. 종료 시 원본 본문은 다시 전체 해시하지 않고 저장 속성을 대조합니다. 같은 크기·fileKey·생성/수정 시각을 의도적으로 복원하는 본문 변경까지 원자적으로 탐지하는 기능은 아니며, 안정된 중지 상태와 외부 신뢰 manifest/스냅샷 검증이 필요합니다. 이는 OS 격리/원자적 스냅샷/증거 보존 제품이 아닙니다. 읽기 전용이어도 OS 접근 시각은 갱신될 수 있습니다.

문제 파일을 자동 재등록하거나 기록 해시를 새 값으로 덮어쓰지 않습니다. 원본을 보존하고 보호된 백업/업무 원장과 대조해 복구 대상을 확인합니다. 백업·격리 복원 절차는 [BACKUP_RECOVERY.md](BACKUP_RECOVERY.md), 캐시 잔재 정리는 [OFFLINE_MAINTENANCE.md](OFFLINE_MAINTENANCE.md)를 참고하세요.

## 검증

합성 원본에 대해 비변경 정상 점검, 동일 크기 손상, 잘림/메타데이터 누락, tenant·경로·SHA 필드 오류, 바이트/항목/결과 상한, 미확인 파일/업로드 잔재 보존, 점검 중 메타데이터 변경, Windows 정션(또는 symlink) 경계, CLI 옵션·JSON 비공개 필드·종료 코드 및 오프라인 help를 검사합니다. 추가 회귀는 실행 quota writer 차단, 같은 JVM/별도 JVM 잠금, marker 전체 수명/변경/출현, 먼저 검증한 원본의 늦은 변경, 크기·mtime을 되돌린 카탈로그 변경, tenant 항목 추가, 문제/부분/예외 이후 잠금 해제, CLI4/5 비노출과 통합 범위 재사용을 포함합니다. 실제 업무 원본에는 실행하지 않습니다. 새로운 외부 도구나 런타임 의존성은 추가하지 않았습니다.
