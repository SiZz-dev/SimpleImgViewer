# 메모·스탬프 실행 취소 / 다시 실행

## 적용 범위

저장에 성공한 메모·스탬프의 추가·내용 수정·이동·크기 변경·삭제를 되돌리거나 다시 적용합니다.
기존 항목 ID·생성 시각·겹침 순서를 복원하고 갱신 시각과 문서 revision은 새 값으로 증가시킵니다.
한 번의 드래그/리사이즈 저장을 한 단계로 기록합니다. 값과 순서가 같은 저장은 단계를 소비하지 않습니다.
실행 취소 후 새 변경을 저장하면 다시 실행 분기를 제거합니다.
범위는 저장된 주석 변경입니다. 보기 밝기/회전·업로드·PNG 다운로드는 별도의 기능입니다.

브라우저가 과거 주석 배열·스탬프 소유자·사용자 경로를 전송해 복원하지 않습니다.
서버가 보관한 항목 차이(before/after)만 사용하며 개인 스탬프 소유 정보는 내부에 유지합니다.
공유 파일의 STAMP 권한이 있는 편집자는 자신이 삭제한 게시 스탬프를 복원할 수 있고,
개인 스탬프 라이브러리의 접근 권한은 기존 소유자에게 유지합니다.

## 설치 YAML

~~~yaml
imagegate:
  editing:
    history:
      enabled: true
      max-steps: 20
      max-contexts: 128
      max-contexts-per-user: 8
      ttl: 30m
~~~

설치 예제 및 기본 application.yml에 반영했습니다. 변경 후 서버 재시작이 필요합니다.
max-steps 1~50, max-contexts 1~256, max-contexts-per-user 1~32 및 전체 상한 이하,
ttl 1분~2시간을 허용합니다. 오타/범위 오류는 시작 시 거부합니다.
enabled=false이면 기록을 보관하지 않고 명령 API도 403으로 차단합니다.
설치 옵션은 사용자별 ANNOTATE/STAMP/VIEW 권한을 대체하지 않습니다.

컨텍스트는 조직·사용자·미디어 ID·원본 버전·페이지·좌표계의 조합입니다.
같은 사용자의 같은 컨텍스트는 여러 탭/새로고침 후에도 같은 서버 기록을 공유합니다.
다른 파일/페이지는 별도 기록이며 UI 전환 후 해당 페이지를 조회할 때 다시 불러옵니다.
최근 변경 시각 기준 TTL을 갱신하며 GET은 만료를 연장하지 않습니다.
만료된 기록은 다음 저장소 접근 시 제거됩니다. 유휴 서버의 즉시 메모리 삭제 타이머는 제공하지 않습니다.
상한에 도달하면 해당 사용자/전체에서 오래 변경하지 않은 컨텍스트를 먼저 제거합니다.
단계 수는 undo/redo를 합한 상한이며 항목 두 개 이하의 값/위치만 기록합니다. PNG·전체 문서 스냅샷은 보관하지 않습니다.
기본 최대 2,560개 차이 기록, 설정 최대 12,800개이며 실제 힙 사용량은 텍스트/참조에 따라 달라집니다.

기록은 단일 서버의 제한된 메모리 상태입니다. 서버 재시작·만료·용량 퇴거 후 명령 기록은 사라집니다.
저장된 주석/스탬프는 기존 디스크 저장소에 유지됩니다. 장기 감사/보존·분산 기록과는 별도입니다.
실제 SSO 로그아웃 이벤트 연동은 후속 작업이며 브라우저의 권한 상실 처리는 화면과 조작 상태를 정리합니다.

## API

기존 주석 문서 응답에 history를 추가했습니다.

~~~json
{
  "enabled": true,
  "canUndo": true,
  "canRedo": false,
  "undoDepth": 2,
  "redoDepth": 0,
  "undoType": "note",
  "redoType": null
}
~~~

카운트와 다음 조작 유형만 반환합니다. 과거 내용/개인 stampOwner/다른 사용자 기록은 반환하지 않습니다.
현재 문서 revision과 일치하고 해당 유형의 현재 권한이 있을 때만 실행 가능 상태를 표시합니다.

POST /api/v1/media/{mediaId}/pages/{page}/annotations/history/undo
POST /api/v1/media/{mediaId}/pages/{page}/annotations/history/redo

~~~json
{
  "mediaVersion": "현재 원본 버전 UUID",
  "coordinateSpaceId": "현재 페이지 좌표계 ID",
  "expectedRevision": 7
}
~~~

CSRF와 신뢰된 인증 주체가 필요합니다. JSON은 16KiB 상한 및 알 수 없는 필드 거부 정책을 적용합니다.
정상 응답은 최신 주석 문서 200, no-store, 새 revision의 ETag입니다.
익명 401, 다른 조직/파일·행위 권한 회수 404, 설치 비활성 403,
낡은 버전/좌표/문서 revision은 EDIT_CONFLICT(409), 없거나 만료/불일치한 기록은 EDIT_HISTORY_UNAVAILABLE(409)입니다.
미리보기/원본 좌표 준비 상태와 현재 개수·내용·이미지 경계를 재확인합니다.
잘못된 방향/입력 400, 본문 상한 413이며 요청에서 항목 목록/스탬프 소유자/복원 경로를 받지 않습니다.

## 충돌·동시성

주석 변경·명령 적용·기록 갱신을 같은 편집 서비스의 직렬화 경계에서 수행하고,
실제 저장은 기존 AnnotationStore의 expectedRevision 검사와 원자적 스냅샷 교체를 사용합니다.
단일 스냅샷 저장소 writer lock을 유지합니다. 뷰잉 PNG/재생 서비스는 이 편집 수명 락에 참여하지 않습니다.
같은 revision의 명령을 두 번 보내면 한 번만 반영되고 두 번째는 409입니다.
외부 사용자의 변경이 들어온 뒤에는 이전 자신의 기록으로 문서를 덮어쓰지 않습니다.
이후 자신의 새 변경은 현재 문서를 시작점으로 새 기록을 만듭니다.
명령 대상 항목의 내용/ID/원래 생성 시각도 비교하고 허가된 한 항목만 복원합니다.

## UI

우측 메모·스탬프 도구에 실행 취소/다시 실행 버튼과 가능한 단계 수를 표시합니다.
Ctrl/⌘+Z는 취소, Ctrl+Y 또는 Ctrl/⌘+Shift+Z는 다시 실행입니다.
input/textarea/select/contenteditable·IME 입력에서는 브라우저의 기본 편집 동작을 유지합니다.
적용 전 메모/크기 입력·저장/업로드·주석 배치/드래그 중에는 기록 명령을 막습니다.
설치 정책/현재 유형 권한도 버튼에 적용하며 서버가 명령마다 다시 검증합니다.
파일/페이지 전환과 권한 상실은 현재 UI 상태를 해제하고 늦은 응답을 epoch로 무시합니다.

충돌이나 응답 유실이 발생하면 최신 문서를 다시 조회하고 결과 확인 안내를 표시합니다.
서버에서 이미 반영됐을 가능성이 있으므로 명령을 자동 재전송하지 않습니다.
최신 조회까지 실패하면 편집 문서를 해제하고 명령을 중지합니다.

## 검증

저장소: 깊이/분기·만료·GET 미연장·사용자/전체 상한·조직/사용자/파일/버전/페이지/좌표계 격리·재시작/비활성·변경 없는 저장.
실제 API: 추가/수정/삭제 복원·ID/순서·revision 증가·이중 요청 단일 반영·외부 변경 보호,
스탬프/공유 게시 스탬프의 사적 소유 정보 보존·현재 권한·CSRF·엄격한 입력/크기 제한.
Chrome: 버튼/단축키·입력창 기본 undo·새 분기·크기/스탬프 복원·충돌·반영 후 응답 유실·늦은 응답·페이지/파일 격리·사용 여부.
실제 SSO/공유 업무 ACL·다중 서버·감사/보존·업무 부하는 후속 검증입니다.
설치 ZIP은 최종 기능 구현과 전체 배포 검증 이후에만 생성합니다.

최종 개발 검증: JDK 21 전체 build -Pimg2tileIntegration -PffmpegIntegration 성공, Java 테스트 229개 통과(실패/오류/건너뜀 0). Chrome 시나리오 20개 통과, viewer-history.png 포함 다크/라이트/모바일·편집 화면 확인. 공유 편집자의 게시 스탬프 복원, 레이어 순서, 중복 요청, 변경 없는 저장, 비활성 정책과 입력 상한 회귀 포함. 설치 ZIP 미생성.
