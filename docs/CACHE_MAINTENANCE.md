# 이미지·재생 캐시 자동 정리

게시 실패·정리 실패·별도 JVM 강제 종료 후 보존/명시적 재시도/maintenance skip 검증은 [PUBLICATION_FAILURE_RECOVERY.md](PUBLICATION_FAILURE_RECOVERY.md)를 참고합니다. 재시도 성공이 고아 파일 자동 삭제를 뜻하지는 않습니다.

## 적용 범위

영상·음성의 비공개 파생 재생본과 이미지 페이지별 PNG 미리보기에 적용합니다.
storage.converted-directory의 playback-v1 / previews-v1에서 정상 완료(ready) 항목과 실패(failed) 상태만 대상으로 합니다.
원본·주석·사용자 스탬프 저장소는 변경하지 않습니다.
queued/running, 중단된 작업 디렉터리, 손상 메타데이터, 예상하지 못한 파일은 자동 삭제하지 않습니다.
손상/비정상 항목은 운영자가 확인할 수 있도록 건수만 경고하며 정상 대기/실행 상태 제외는 경고하지 않습니다. 로그에 파일명·경로·조직·사용자·미디어 ID를 남기지 않습니다.

## 설치 설정

~~~yaml
imagegate:
  preview:
    cache:
      enabled: true
      retention: 7d
      cleanup-interval: 5m
      max-bytes: 5368709120 # 5 GiB
  playback:
    cache:
      enabled: true
      retention: 7d
      cleanup-interval: 5m
      max-bytes: 10737418240 # 10 GiB
~~~

config/imagegate.example.yml과 기본 application.yml에 반영했습니다.
운영 설정 변경 후 재시작합니다. cache.enabled=false이면 자동 정리를 중단하며 기존 재생/변환 정책은 별도입니다.
preview/playback.enabled=false여도 각 cache.enabled=true이면 기존 캐시를 정리합니다.
이미지 큐는 preview.enabled 또는 preview.cache.enabled 중 하나가 활성일 때 worker.lock을 확보해 다른 서버와 경합하지 않게 합니다.
허용 범위: retention 1시간~365일, cleanup-interval 1분~1일, max-bytes 1MiB~1TiB.
잘못된 값·오타는 시작 시 거부합니다. 이 옵션은 사용자 권한 부여와 무관합니다.

## 정리 기준과 속도

전용 단일 데몬 스레드가 시작 후 cleanup-interval이 지나면 첫 정리를 수행하고,
정리가 끝난 후 같은 간격으로 다음 정리를 수행합니다. HTTP 요청 안에서 전체 캐시를 스캔하지 않습니다.
각 종류의 기간이 지난 항목을 제거하며 해당 정상 산출물 합계가 max-bytes를 넘으면 오래 사용하지 않은 항목부터 제거합니다.
접수/완료 캐시 재사용/콘텐츠 전송에서 사용 수명을 확보하며, 사용 시각은 상태 파일 수정 시각으로 유지합니다.
읽기 요청마다 상태 파일을 재작성하지 않고 최대 1분 단위로 수정 시각만 갱신하므로 재시작 후에도 근사 LRU를 유지합니다.
상태 조회 GET 자체는 사용 시각을 갱신하거나 변환을 접수하지 않습니다.

스캔은 캐시 키 디렉터리의 한 단계와 각 항목의 직접 자식만 검사합니다.
항목별 짧은 동기화로 상태 교체와 충돌을 방지하며 전체 스캔 동안 서비스/캐시 락을 잡지 않습니다.
후보 메모리와 1회 퇴거는 가장 오래된 최대 1,000개로 제한합니다. 디렉터리 순회 자체는 전체 항목 수에 비례합니다.
대규모 배포의 최초 열람/Range 지연 P95와 실제 디스크 부하는 별도로 측정해야 합니다.

max-bytes는 **해당 종류의 검증된 완료 산출물 바이트의 주기 정리 목표**입니다.
영상·음성 합계는 playback.cache, 이미지 PNG 합계는 preview.cache로 별도 관리합니다.
변환 중 임시 파일·상태 파일·손상/알 수 없는 파일·원본은 이 합계에 포함하지 않습니다.
사용 중인 항목이나 1회 정리 한도 때문에 목표를 초과할 수 있습니다. 전체 디스크의 하드 할당량이 아닙니다.
운영 전용 볼륨/OS 할당량·남은 공간 경보는 별도로 필요합니다.

## 동시성·보안

변환 접수부터 워커 종료까지 참조 수명(lease)을 유지합니다.
HTTP GET/HEAD는 메타데이터 확인 전부터 응답 콜백 종료까지 수명을 유지합니다.
부분 전송·클라이언트 연결 종료·예외도 finally/try-with-resources에서 해제합니다.
동시에 여러 전송이 있으면 마지막 수명이 끝나기 전까지 해당 캐시를 삭제하지 않습니다.
수명 보호는 캐시 보존만 담당하며 모든 요청의 최신 VIEW/조직/원본 버전 검사를 유지합니다.

후보 선택 후 사용 시각/상태/파일/수명을 다시 검사한 뒤 삭제합니다.
정규 캐시 키·정상 상태 파일·검증된 불변 재생본만 허용하며, 링크·별칭 경로·추가 파일/하위 폴더가 있으면 건너뜁니다.
알려진 파일과 빈 항목 디렉터리만 제거합니다. 재귀 삭제/브라우저 제공 경로/외부 명령을 사용하지 않습니다.
단일 저장소 writer lock을 유지합니다. 여러 서버가 같은 캐시를 공유하는 분산 구성은 지원하지 않습니다.
OS 계정/저장소 ACL은 필수이며, 악의적 로컬 관리자의 동시 파일 교체까지 방어하는 OS 격리는 별도입니다.

삭제된 캐시는 not_requested로 돌아갑니다. GET은 변환을 시작하지 않습니다.
파일을 다시 선택하거나 명시적인 POST 준비 요청을 보내면 원본에서 다시 생성합니다.
상태 조회 후 콘텐츠 요청 사이에 퇴거되면 이미지는 404, 재생은 NOT_READY(409)이며 원본/다른 파일로 우회하지 않습니다.

## 검증

저장소 테스트는 기간 만료/실패 상태, 용량 초과 LRU, 다중 수명/중복 해제, 재시작 시 사용 시각,
비정상/추가 파일/작업 폴더 보존, 비활성/종료, 미래 시각, 1회 1,000개 한도를 확인합니다.
서비스 테스트는 응답 콜백 중 강제 정리에도 파일이 보존되는지, 전송 예외 후 수명이 해제되는지,
퇴거 뒤 GET 미접수·명시적 준비에서 재생성되는지를 확인합니다.
외부 모듈/Range/권한 회귀는 build -Pimg2tileIntegration -PffmpegIntegration으로 실행합니다.
설치 ZIP은 최종 구현 및 전체 배포 검증 이후에만 생성합니다.

최종 개발 검증: JDK 21 전체 build 및 실제 img2tile/FFmpeg 통합 포함 Java 테스트 198개 통과(실패/오류/건너뜀 0). UI 변경은 없으며 이번 단계는 서버 캐시 수명 검증에 집중했습니다. 설치 ZIP 미생성.

## 이미지 수명과 편집 데이터

이미지는 고정 64개 키 기반 잠금을 그대로 사용하고, 수명 참조 수는 활성 항목만 동시 맵에 유지합니다.
변환과 동기식 GET/HEAD 콜백 전체에서 PNG를 보호하며 파일 경로를 반환한 뒤 비동기 Resource 전송에 넘기지 않습니다.
완료 시각/정리 옵션은 캐시 키에 추가하지 않아 설정 조정만으로 모든 이미지를 재변환하지 않습니다.
원본 버전/페이지/EXIF 방향으로 좌표계 ID를 유지하고 저장된 주석과 스탬프는 별도 저장소에서 재사용합니다.
캐시가 없을 때 편집을 요구하면 기존 준비 상태 검증에 따라 거부될 수 있으며 PNG를 재준비하면 편집 문서를 다시 조회할 수 있습니다.
통합 테스트는 실제 주석과 사용자 스탬프를 저장한 뒤 캐시를 제거·재생성하여 문서 revision/항목·좌표계와 스탬프 콘텐츠를 비교합니다.

이미지 확장 후 최신 검증: JDK 21 전체 build -Pimg2tileIntegration -PffmpegIntegration 성공. Java 테스트 207개 통과(실패/오류/건너뜀 0). PNG GET/HEAD 권한·정리 중 수명 보호·전송 예외 해제·저장된 메모/스탬프/좌표계 복원 포함. UI 변경 없음, 이번 단계 브라우저 재실행 없음. 설치 ZIP 미생성.

## 썸네일 포함

이미지 캐시의 전용 썸네일을 미리보기와 같은 수명으로 보호하며 max-bytes에는 두 PNG를 합산합니다. 퇴거 시 정상 메타데이터가 가리키는 두 파일을 함께 제거합니다. THUMBNAILS.md를 참고하세요.

## 비정상 종료 잔재의 오프라인 처리

현재 참조되지 않은 게시 결과·메타데이터 임시 파일·알려진 work 폴더는 OFFLINE_MAINTENANCE.md의 별도 관리 도구로 점검합니다. 기본 dry-run이며 중지 확인/명시적 apply/두 캐시의 writer lock/파일 재검증을 요구합니다. 원본/crop/주석/스탬프 잔재 및 임의 트리는 정리하지 않습니다. 일반 캐시 정리의 보수적 제외 정책은 유지합니다.
